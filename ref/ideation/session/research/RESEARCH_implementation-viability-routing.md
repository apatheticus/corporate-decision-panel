# Research: Implementation Viability & Routing Mechanism

**Requested by:** Free-thinker's questions on roster size viability and CEO routing mechanism
**Date:** 2026-02-22

## Questions
1. Is 37 separate agent instances viable, or should team leads be sequential calls within a single C-suite agent?
2. Should CEO-level routing (selective team activation) be a core feature or v2?

## Findings

### Part 1: Implementation Viability -- 37 Agents

#### The Hard Numbers

From the official Claude Code cost documentation:
- Average cost: **$6/developer/day**, $100-200/developer/month with Sonnet
- Agent teams use approximately **7x more tokens** than standard sessions
- Token usage scales linearly with number of active teammates
- Each teammate maintains its own context window as a separate Claude instance

#### The Math on Full Deployment (37 Agents Simultaneously)

If a single agent interaction costs ~$0.50-1.00 in tokens:
- 37 simultaneous agents = **$18.50-37.00 per decision** (rough estimate)
- With Opus for CEO + Sonnet for C-suite + Haiku for team leads, this drops significantly
- Haiku is ~10x cheaper than Opus, Sonnet is ~3x cheaper than Opus

**Key cost optimization from docs:** "Teams using economic orchestration report 40-60% cost reductions compared to uniform subagent deployment, while maintaining or improving output quality."

#### The Architectural Constraint

From the Claude Code Agent Teams documentation (my earlier research):
- **No nested teams**: Teammates cannot spawn their own teams
- **One team per session**: A lead can only manage one team at a time
- **Subagents cannot spawn subagents**: No recursive delegation

This means a literal three-tier agent hierarchy (CEO team -> C-suite teams -> team leads) is **not possible** with current Agent Teams. The architecture must work within a flat structure.

#### Three Viable Implementation Patterns

**Pattern A: Flat Agent Team (All 37 as teammates)**
- CEO is team lead, all 36 others are teammates
- Technically possible but impractical: 36 simultaneous Claude instances
- Massive token cost, coordination overhead
- Loses the hierarchical cascade (C-suite doesn't "manage" team leads)
- **Verdict: Not recommended**

**Pattern B: Staged Execution (Recommended for v1)**
- The skill runs as a **single agent session** using **sequential subagent calls**
- CEO agent is the main session
- Each C-suite member is invoked as a **subagent** (one at a time or in parallel batches)
- Within each C-suite subagent call, the system prompt includes team lead perspectives as **structured analysis sections** rather than separate agents
- Team lead "analysis" is generated by the C-suite subagent using its system prompt's domain framework and checklists

How this works in practice:
```
Main session (CEO agent, Opus)
  ├── Subagent: COO (Sonnet) -- generates COO + 5 team lead analyses
  ├── Subagent: CFO (Sonnet) -- generates CFO + 5 team lead analyses
  ├── Subagent: CTO (Sonnet) -- generates CTO + 4 team lead analyses
  ├── Subagent: CISO (Sonnet) -- generates CISO + 4 team lead analyses
  ├── Subagent: VP Sales (Sonnet) -- generates VP Sales + 4 team lead analyses
  ├── Subagent: VP Delivery (Sonnet) -- generates VP Delivery + 4 team lead analyses
  └── Subagent: CAO (Sonnet) -- generates CAO + 4 team lead analyses
```

- **7 subagent calls** (can run in parallel)
- Each C-suite subagent's system prompt includes team lead personas and analytical checklists
- The C-suite agent "simulates" the team lead consultation by working through each team lead's analytical framework sequentially within its own context
- CEO receives 7 structured reports and synthesizes

**Advantages:**
- Only 8 context windows (1 CEO + 7 subagents)
- Subagents can run in parallel (all 7 simultaneously)
- Each subagent's system prompt includes full team lead framework
- Prompt caching reduces cost for repeated system prompt content
- Summary returns to CEO context, keeping it clean
- Works within all current Claude Code constraints

**Disadvantages:**
- Team lead "analysis" is simulated by C-suite agent, not truly independent
- A single model generating both manager and report perspectives may produce less diversity than separate agents
- But research showed: "heterogeneous agents help" and "independent drafting is the most important pattern" -- the 7 C-suite subagents ARE independent of each other, which captures the primary benefit

**Token cost estimate:**
- 7 Sonnet subagent calls: ~$3.50-7.00
- 1 Opus CEO synthesis: ~$1.00-2.00
- Total per decision: **~$4.50-9.00** (vs. $18-37 for 37 separate agents)
- With selective routing (3-5 C-suite): **~$2.50-5.00**

**Pattern C: Hybrid Agent Team + Subagents (Recommended for v2)**
- CEO is team lead of an Agent Team
- 7 C-suite members are Agent Team teammates (parallel, can communicate)
- Each C-suite teammate uses subagents for team lead analysis
- C-suite teammates can challenge each other via messaging (Phase 4.5)
- Requires the GitHub #24316 feature (custom agent definitions for teammates) for full effectiveness

**Advantages:**
- True inter-agent C-suite deliberation
- Each C-suite teammate can use subagents for team leads
- Wait -- subagents cannot spawn subagents

**Problem:** Agent team teammates are full Claude Code instances, but the docs don't specify whether teammates can spawn subagents. Based on the architecture:
- Subagents work "within a single session"
- Teammates ARE separate sessions
- So teammates SHOULD be able to spawn their own subagents

If teammates can spawn subagents, Pattern C becomes:
```
Agent Team Lead: CEO (Opus)
  ├── Teammate: COO (Sonnet) --> spawns subagents for team leads (Haiku)
  ├── Teammate: CFO (Sonnet) --> spawns subagents for team leads (Haiku)
  ├── ... (7 C-suite teammates total)
```

This would give true three-tier execution with inter-C-suite communication. But it requires:
1. Confirmation that teammates can spawn subagents (not documented)
2. Custom agent definitions for teammates (feature request #24316)
3. Significantly higher token budget

**Verdict: v2 aspiration, not v1 design**

#### Recommendation

**v1: Pattern B (Staged Execution with Subagents)**
- CEO main session + 7 C-suite subagents (parallel)
- Team lead analysis simulated within each C-suite subagent's prompt
- Selective routing reduces to 3-5 subagents for most decisions
- Cost: ~$2.50-9.00 per decision depending on depth and routing

**v2: Pattern C (Hybrid) if constraints are lifted**
- Agent team for C-suite inter-communication
- Subagents within teammates for team leads
- Full three-tier with cross-functional deliberation

### Part 2: CEO Routing Mechanism

#### Why Routing Is Core, Not v2

The math is clear: every C-suite subagent call costs real tokens. Without routing:
- Every question, no matter how small, triggers 7 subagent calls + team lead analysis
- A "should we switch project management tools?" gets the same treatment as "should we acquire CompetitorX?"
- This is both expensive and produces unnecessary noise

With routing:
- CEO classifies the decision and activates only relevant C-suite members
- A PM tool switch might only need COO + CTO + CFO (3 calls instead of 7)
- Token savings: 40-60% on most decisions

#### How Routing Works in Multi-Agent Systems

Research on adaptive routing in multi-agent systems shows:
- **Task classification as first step**: An intent classifier matches incoming requests to appropriate specialist agents
- **Two-layer architecture**: Adaptive controllers predict task parameters and select a relevant subset of agents; tasks are "made visible only to a restricted group"
- **Multi-parameter routing**: Consider task complexity, priority, agent capabilities, and relevance
- **Reinforcement learning**: Routing policies evolve based on observed performance

#### Recommended Routing Design

The CEO's Phase 1 (Framing) should include a routing step:

```
Decision Classification:
├── Decision Type: [Strategic | Financial | Operational | Technical | Security | Personnel | Mixed]
├── Scope: [Company-wide | Department | Team | Individual]
├── Urgency: [Critical | Standard | Exploratory]
├── Complexity: [Simple | Moderate | Complex | Transformative]
└── Analysis Depth: [Quick (3 agents) | Standard (5 agents) | Thorough (7 agents)]
```

**Routing Rules (examples):**

| Decision Type | Always Activate | Conditionally Activate | Typically Skip |
|---|---|---|---|
| **Financial** (investment, acquisition, budget) | CFO, COO, CEO | CTO, VP Sales, VP Delivery | CISO (unless IT/data related), CAO |
| **Technical** (build/buy, architecture, tools) | CTO, CISO, CFO | COO, VP Delivery | VP Sales, CAO |
| **Security** (breach response, compliance, policy) | CISO, CTO, CAO | CFO, COO | VP Sales, VP Delivery |
| **Strategic** (new market, acquisition, pivot) | ALL | -- | -- |
| **Operational** (process change, tool adoption) | COO, CFO | CTO, VP Delivery | CISO, VP Sales, CAO |
| **Personnel** (hiring, reorg, culture) | CAO, COO, CFO | VP Delivery, VP Sales | CTO, CISO |
| **Sales/Growth** (pricing, market entry, partnerships) | VP Sales, CFO, VP Delivery | CTO, COO | CISO, CAO |

**The user should be able to override routing.** If they want all 7 perspectives on a simple question, they should be able to request "thorough" mode. And if they want a quick take from just the CFO and CISO, they should be able to specify that.

#### Routing Implementation in the Skill

The routing mechanism should be:
1. **Automatic by default**: CEO classifies and routes based on decision type
2. **User-overridable**: User can specify which roles to consult
3. **Transparent**: The decision record shows which roles were consulted and why others were excluded
4. **Depth-selectable**: Quick (3 agents) / Standard (5 agents) / Thorough (all 7)

## Key Takeaways
- **37 simultaneous agents is not viable in v1.** The recommended architecture is Pattern B: CEO main session + 7 C-suite subagents, with team lead analysis simulated within each subagent's system prompt via structured analytical frameworks and checklists.
- **This pattern costs ~$2.50-9.00 per decision** depending on routing and depth, vs. $18-37 for 37 separate agents.
- **CEO routing is a CORE feature, not v2.** Without it, every question gets the same expensive treatment. Routing reduces cost 40-60% for most decisions and produces less noise.
- **The routing mechanism classifies by decision type, scope, urgency, and complexity** to determine which C-suite members to activate and at what depth.
- **v2 aspiration: Pattern C (Agent Team + Subagents)** would enable true inter-C-suite communication but requires features not yet available.
