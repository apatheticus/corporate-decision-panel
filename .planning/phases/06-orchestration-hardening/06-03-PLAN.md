**YAML frontmatter:**
```yaml
---
name: cdp:cleanup
description: Clean up old CDP session directories
argument-hint: "[--older-than days?]"
---
```

**Command body:** After the frontmatter, write markdown instructions for the agent that executes this command. The instructions must cover:

1. **Session discovery:** Scan `.cdp-output/` directory for session directories. Each directory follows the naming convention `YYYY-MM-DD_<issue-slug>/`. If `.cdp-output/` does not exist or is empty, inform the user that no sessions exist and exit.

2. **Age filtering:** Parse the `YYYY-MM-DD` prefix from each directory name to determine session age. Default threshold: 30 days. If the user provides `--older-than N`, use N days instead. List only sessions older than the threshold as candidates for deletion.

3. **Size calculation:** For each candidate session, calculate directory size using `du -sh`.

4. **Confirmation table:** Display a table of candidate sessions with columns: Date | Session Slug | Size. Show the total number of sessions and total size. If no sessions match the age threshold, inform the user and exit.

5. **Confirmation prompt:** Ask the user for explicit confirmation before proceeding with deletion. Example: "Delete these N sessions? (yes/no)"

6. **Deletion:** On confirmation, remove each candidate session directory entirely (`rm -rf`). Clean deletion -- no RECORD.md archiving. Per user decision: "users who want to preserve records should export or version-control separately."

7. **Completion message:** Report how many sessions were deleted and how much space was reclaimed.

**Edge cases to handle:**
- No `.cdp-output/` directory: inform user, exit
- No sessions older than threshold: inform user, exit
- User declines confirmation: exit without deleting anything

**Do NOT:**
- Archive or preserve RECORD.md before deletion
- Delete sessions from today or recent sessions (the 30-day default prevents this)
- Require any external libraries -- use standard shell commands (ls, du, rm, date)
